# 持仓复盘与盈亏趋势设计

## 背景

当前持仓模块已经以流水作为事实来源，可以计算当前持仓、移动加权平均成本、未实现盈亏和已实现盈亏。用户下一步需要的不只是看当前结果，还需要从交易流水中复盘资金投入、卖出回收、手续费和已实现盈亏的变化节奏。

第一版复盘趋势只使用现有流水数据，不引入历史行情回测。原因是应用虽然有行情历史，但历史行情采样不一定覆盖每笔交易日，若直接按历史价格估算历史市值，容易给出不可靠曲线。

## 目标

- 在持仓卡片中新增“复盘”分段视图。
- 按币种分别展示 RMB/克 和 USD/oz 的流水复盘，不做跨币种折算。
- 从流水聚合交易次数、买入金额、卖出回收、手续费、已实现盈亏和净投入。
- 按交易日期生成趋势点，展示累计净投入、累计已实现盈亏和剩余数量。
- 行情刷新时继续保留正在编辑的持仓或流水输入。
- 复盘数据随现有 `portfolio_updated` 状态返回，不新增 Socket 事件。

## 非目标

- 不做历史市值、历史未实现盈亏或历史总资产回测。
- 不引入 FIFO、税务批次、IRR、年化收益率或最大回撤。
- 不做 RMB 与 USD 的汇率折算。
- 不新增持久化文件，复盘数据由流水实时派生。
- 不改变现有持仓和流水导出契约。

## 方案选择

采用方案 A：在现有持仓状态中增加 `review` 字段，前端新增第三个分段视图。

备选方案：

- 方案 B：新增独立 Socket 事件按需获取复盘。优点是初始状态更轻；缺点是当前持仓数据量很小，新增事件会增加同步和错误路径。
- 方案 C：前端直接从 `transactions` 计算复盘。优点是改动少；缺点是成本和已实现盈亏规则会在前后端重复，后续容易不一致。

选择方案 A 的原因：

- 后端已经掌握流水排序、校验和已实现盈亏计算规则。
- 前端只负责展示，避免重复实现成本算法。
- 复盘视图与持仓状态同生命周期，行情刷新和保存流水后自然更新。

## 数据契约

`build_portfolio_state_from_transactions` 返回结构增加：

```json
{
  "review": {
    "rmb": {
      "mode": "rmb",
      "trade_count": 0,
      "buy_count": 0,
      "sell_count": 0,
      "buy_amount": 0.0,
      "sell_amount": 0.0,
      "fee_total": 0.0,
      "realized_pnl": 0.0,
      "net_invested": 0.0,
      "current_quantity": 0.0,
      "cost_basis": 0.0,
      "average_cost": null,
      "first_trade_date": "",
      "last_trade_date": "",
      "points": []
    },
    "usd": {}
  }
}
```

字段定义：

- `buy_amount`：买入成交金额加手续费。
- `sell_amount`：卖出成交金额扣除手续费。
- `fee_total`：买入和卖出手续费合计。
- `realized_pnl`：卖出流水产生的已实现盈亏合计。
- `net_invested`：累计买入支出减累计卖出回收。
- `current_quantity`：按流水回放后的剩余数量。
- `cost_basis`：按移动加权平均成本回放后的剩余成本。
- `points`：按交易日期聚合后的趋势点。

趋势点结构：

```json
{
  "date": "2026-06-25",
  "trade_count": 1,
  "buy_amount": 0.0,
  "sell_amount": 0.0,
  "fee": 0.0,
  "realized_pnl": 0.0,
  "cumulative_buy_amount": 0.0,
  "cumulative_sell_amount": 0.0,
  "cumulative_fee": 0.0,
  "cumulative_realized_pnl": 0.0,
  "net_invested": 0.0,
  "quantity": 0.0,
  "cost_basis": 0.0
}
```

日期为空的流水使用 `created_at` 的日期部分；仍无法得到日期时归入“未标日期”。

## 后端设计

在 `goldmonitor/portfolio.py` 中新增复盘聚合函数：

- 复用 `normalize_portfolio_transactions` 和 `replay_portfolio_transactions`。
- 使用回放后的 `enriched_transactions` 中的 `realized_pnl`，不重新计算卖出盈亏。
- 按币种维护独立汇总和趋势点。
- 返回空复盘结构，保证无流水时前端也有稳定字段。

`build_portfolio_state_from_transactions` 将 `review` 放入返回状态。旧持仓兼容路径通过迁移流水后同样获得复盘数据。

## 前端设计

模板中 `portfolioViewTabs` 增加第三个按钮：`复盘`。

前端状态：

- `portfolioView` 支持 `positions`、`transactions`、`review`。
- `normalizePortfolioState` 复制并保留后端 `review`。
- `setPortfolioView` 只接受上述三种视图，非法值回到 `positions`。

复盘视图内容：

- 顶部展示两张币种复盘摘要卡。
- 每张卡展示净投入、已实现盈亏、手续费、交易次数、持有数量和最近交易日期。
- 下方展示趋势点列表，每个日期一行，包含净投入、已实现盈亏和剩余数量。
- 无流水时展示空状态。

视觉方向：

- 复用现有深色、紧凑、数据面板风格。
- 不新增大图和装饰背景。
- 使用一条细轨迹条表达累计净投入占比，作为复盘视图的记忆点。
- 所有文本在窄栏下允许换行或截断，不撑出视窗。

## 异常路径

- 流水为空：返回空复盘，前端显示“暂无复盘数据”。
- 单个币种无流水：该币种卡显示 0 值和空趋势。
- 流水日期为空：按创建日期聚合；仍无创建日期则显示“未标日期”。
- 行情缺失：不影响复盘，因为第一版不计算历史市值。
- 卖出数量非法：沿用现有保存校验，不生成复盘状态。

## 测试

- 后端测试复盘字段存在，空流水结构稳定。
- 后端测试同一币种多日买入、卖出、手续费和已实现盈亏聚合正确。
- 后端测试 RMB 和 USD 分开聚合，不互相污染。
- 前端资产检查新增第三个分段入口、复盘渲染函数和样式选择器。
- JS 语法检查保证新增渲染函数可解析。
- 浏览器验证桌面和窄屏下复盘视图不横向溢出。
