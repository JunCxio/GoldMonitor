# GoldMonitor 扩展边界前置条件

本文档用于约束 GoldMonitor 的产品边界扩展。多品种贵金属、更多通知渠道、局域网只读面板和云同步都不应在基础能力未稳定前启动。

## 扩展前必须完成

- 阶段 1：模块边界整理
  - `app.py` 不再承载新增业务逻辑。
  - 后端核心业务逻辑可以脱离 Flask 和 Socket.IO 测试。
  - 前端状态、渲染和事件处理具备可拆分边界。

- 阶段 2：本地数据能力完善
  - 本地存储路径有统一清单。
  - 版本化 JSON 数据有 schema metadata 和迁移判断。
  - 诊断报告能说明数据文件存在性、格式、预期版本和迁移状态。

- 阶段 3：持仓、预警、复盘闭环
  - 持仓有用户可理解的状态分层。
  - 持仓提醒触发后能在持仓状态和复盘链路中体现。
  - 警报、交易、行情和风险分析可以被串联复盘。

- 阶段 4：行情可信度增强
  - 后端输出可解释的连续行情质量评分及逐项扣分依据。
  - 每个内置数据源保留有限滚动成功率、缓存率、延迟、连续失败和恢复时间。
  - 数据源异常、缓存回退、数据新鲜度和源间价差异常有明确状态。
  - 页面明确当前主源，并允许在每类至少保留一个启用源的约束下调整内置数据源顺序。
  - 风险分析和页面展示不把低质量数据当作正常行情。

## 可进入的扩展方向

- 多品种贵金属：仅在行情源、估值单位、持仓模型和提醒规则能按品种隔离后启动。
- 更多通知渠道：仅在通知投递状态、重发和静默策略可以复用后启动。
- 局域网只读面板：仅在访问控制、只读数据契约和桌面端单实例行为明确后启动。
- 云同步：仅在本地数据迁移、冲突解决、敏感信息保护和恢复流程明确后启动。

## 暂不进入的范围

- 不在基础阶段内引入账户系统。
- 不在基础阶段内引入远程写入能力。
- 不在基础阶段内把 GoldMonitor 扩成通用金融资产看板。
- 不用临时配置开关绕过数据迁移、权限和安全问题。
