# PRD：目标价观察清单

## 1. Summary

目标价观察清单用于让用户保存多个关注价位，并为每个价位设置方向、备注、启停状态和触发状态。它补充现有固定阈值预警，让用户能更自然地记录“我为什么关注这个价格”和“这个价格是否已经触发”。

第一版不重构现有阈值系统。它以独立清单方式接入现有价格刷新、告警记录、通知和本地持久化链路。

## 3. Background

GoldMonitor 当前已经支持上涨、下跌、关键价位和短时波动提醒。现有提醒配置更像一组固定规则，适合快速设置上下限，但不适合保存多个具体观察目标。

用户在真实使用中可能同时关注多个价位。例如：

- 人民币克价跌到某个价格时考虑买入。
- 国际金价突破某个位置时重点观察。
- 某个价位只在本周有效。
- 某个目标价背后有个人备注，需要触发后回看。

当前项目已经具备这项能力的基础：

- 后端已有 `thresholds`、`volatility_config`、`emit_alert`、`alert_log` 等告警链路。
- 前端右侧已经有预警阈值区域和警报记录区域。
- 本地已有 JSON 和 SQLite 持久化模式。
- Socket.IO 已经承担设置、价格更新和告警推送。

因此，目标价观察清单适合作为下一轮功能扩展。

## 4. Objective

### 目标

让用户可以维护多个目标价，并在价格达到目标时触发提醒和记录。功能要保持本地优先，不引入账号体系或云同步。

### 用户收益

- 可以同时关注多个价位。
- 每个价位可以写清关注原因。
- 触发后可以在警报记录中回看。
- 不需要反复修改现有固定阈值。

### 项目收益

- 增强 GoldMonitor 的核心监控能力。
- 为后续预警策略模板、事件时间轴和复盘报告打基础。
- 在不大改架构的前提下提高产品可用性。

### Key Results

- KR1：用户可以新增、编辑、删除、启用和停用目标价观察项。
- KR2：目标价触发后会生成警报记录，并复用现有通知分发链路。
- KR3：观察清单重启后仍能恢复，配置丢失率为 0。
- KR4：无效价格、无效方向、配置目录不可写等异常路径都有明确提示。
- KR5：新增后端契约测试覆盖持久化、触发、删除和无效输入。

## 5. Market Segment(s)

### 主要用户

需要长期关注黄金价格的个人用户和小型投资者。他们的问题不是“是否知道当前价格”，而是“我关心的多个价格是否已经接近或触发”。

### 使用场景

- 用户设置多个 RMB/克 目标价，用于观察买入或卖出窗口。
- 用户设置 USD/oz 目标价，用于关注国际黄金走势。
- 用户给目标价添加备注，如“上周低点”“预算价位”“突破观察”。
- 用户在触发后查看警报记录，并决定是否确认或继续观察。

### 约束

- 第一版只服务单机本地使用。
- 不做云同步。
- 不做交易建议。
- 不自动调用风险分析模型。
- 不替换现有固定阈值功能。

## 6. Value Proposition(s)

### 用户任务

用户想把多个关注价位保存下来，并在触发后知道“哪个价位触发、为什么关注、当时价格是多少”。

### 获得的价值

- 更少重复配置。
- 更少漏看关键价位。
- 更容易回看触发原因。
- 更适合长期观察，而不只是临时提醒。

### 避免的问题

- 避免把多个关注价位混在单个上下限阈值里。
- 避免触发后不知道当初为什么设置这个价位。
- 避免每次切换观察目标都覆盖原有阈值。

### 相对现有能力的改进

现有阈值功能回答“价格是否超过某个固定上限或下限”。目标价观察清单回答“我关注的多个目标中，哪个已经触发，触发原因是什么”。

## 7. Solution

### 7.1 UX / User Flow

第一版入口放在右侧预警区域，位于现有“预警阈值”卡片下方或卡片内部的独立分组。

基本流程：

1. 用户点击“新增观察”。
2. 用户选择单位：RMB/克 或 USD/oz。
3. 用户选择方向：价格上涨至目标价、价格下跌至目标价。
4. 用户输入目标价格。
5. 用户可选填写备注。
6. 用户保存后，清单显示该观察项。
7. 后台价格刷新时检查观察项。
8. 价格达到目标后，观察项标记为已触发，并生成警报记录。
9. 用户可以停用、重新启用、编辑或删除观察项。

### 7.2 Key Features

#### 新增观察项

用户可以创建一个目标价观察项。必填字段包括单位、方向和目标价格。备注可选。

验收标准：

- 价格必须是大于 0 的数字。
- 单位只能是 `rmb` 或 `usd`。
- 方向只能是 `rise_to` 或 `fall_to`。
- 保存成功后，所有已连接前端都收到最新观察清单。

#### 编辑观察项

用户可以修改已有观察项的价格、方向、备注和启停状态。

验收标准：

- 编辑不存在的观察项时返回错误。
- 修改价格或方向后，触发状态应重置。
- 停用的观察项不会触发提醒。

#### 删除观察项

用户可以删除不再需要的观察项。

验收标准：

- 删除成功后，清单立即更新。
- 删除不存在的观察项时返回明确错误。

#### 触发提醒

每次价格刷新后，系统检查启用且未触发的观察项。

验收标准：

- `rise_to`：当前价格大于或等于目标价格时触发。
- `fall_to`：当前价格小于或等于目标价格时触发。
- 触发后调用现有 `emit_alert`。
- 警报记录中能看出该提醒来自目标价观察清单。
- 已触发的观察项不会在未重置前重复触发。

#### 持久化

观察清单保存到本地文件。

建议第一版新增：

```text
watch_targets.json
```

文件位置与 `settings.json`、`thresholds.json` 保持一致，位于 GoldMonitor 本地数据目录。

验收标准：

- 程序启动时读取观察清单。
- 保存失败时前端显示错误。
- 文件不存在时返回空清单。
- 文件格式异常时不影响主程序启动，返回空清单并记录日志。

#### 配置导出和诊断报告

第一版建议将观察清单纳入诊断报告。是否纳入配置导出可以在实现前确认。

验收标准：

- 诊断报告包含观察项数量和最近触发状态。
- 不包含敏感信息，因为观察清单不应保存密钥。

### 7.3 Technology

#### 后端入口

建议新增常量和全局状态：

```python
WATCH_TARGETS_PATH = os.path.join(APPDATA_DIR, "watch_targets.json")
watch_targets = []
```

建议新增函数：

- `normalize_watch_target(item)`
- `load_watch_targets()`
- `save_watch_targets(items=None)`
- `get_watch_targets_state()`
- `upsert_watch_target(data)`
- `delete_watch_target(target_id)`
- `check_watch_targets(now_str)`

建议新增 Socket.IO 事件：

- `set_watch_target`
- `delete_watch_target`
- `toggle_watch_target`
- `reset_watch_target`

建议新增推送事件：

- `watch_targets_updated`
- `watch_target_error`

#### 数据结构

第一版建议字段：

```json
{
  "id": "target-...",
  "mode": "rmb",
  "direction": "fall_to",
  "price": 688.0,
  "note": "预算观察价",
  "enabled": true,
  "triggered": false,
  "created_at": "2026-06-12T10:00:00",
  "updated_at": "2026-06-12T10:00:00",
  "triggered_at": "",
  "last_trigger_price": null
}
```

第一版不加入有效期字段。有效期可以作为第二版扩展，避免一次性扩大范围。

#### 触发链路

当前价格刷新后已有阈值检查：

- `_check_thresholds("usd", price_usd, now_str)`
- `_check_thresholds("rmb", price_rmb, now_str)`
- `_check_volatility(now_str)`

目标价观察清单可以在同一价格刷新链路中调用：

```python
check_watch_targets(now_str)
```

触发时构造现有告警结构，并补充来源字段：

```python
{
  "time": now_str,
  "type": "warning",
  "mode": "rmb",
  "message": "...",
  "source": "watch_target",
  "watch_target_id": "target-..."
}
```

#### 前端入口

建议在 `templates/index.html` 中新增观察清单区域：

- 清单列表。
- 新增或编辑表单。
- 启用、停用、删除、重置触发状态按钮。

前端状态建议：

- `watchTargets`
- `activeWatchTargetId`
- `watchTargetStatusMessage`

### 7.4 Assumptions

- 用户确实需要多个目标价，而不是只需要当前固定阈值。
- 第一版不需要有效期，也能满足主要场景。
- 观察项触发后默认不重复提醒，符合用户对“目标价达成”的理解。
- 复用现有通知渠道可以满足第一版，不需要为每个观察项单独配置邮件或 Webhook。
- 右侧预警区域可以容纳观察清单，不需要先重做整体布局。

## 8. Release

### First Version

第一版范围：

- 新增、编辑、删除观察项。
- 支持 RMB/克 和 USD/oz。
- 支持上涨至目标价、下跌至目标价。
- 支持备注。
- 支持启用和停用。
- 触发后进入现有警报记录。
- 本地持久化到 `watch_targets.json`。
- 启动时恢复观察清单。
- 增加后端契约测试。

不包含：

- 有效期。
- 分观察项通知渠道。
- 策略模板。
- 云同步。
- 自动风险分析。
- 复杂分组或标签。

### Future Versions

后续可以考虑：

- 有效期。
- 目标价分组。
- 触发后自动归档。
- 从警报详情一键生成目标价。
- 与事件时间轴和复盘报告整合。
- 与预警策略模板整合。

### Estimated Effort

建议拆成 3 个开发阶段：

1. 后端数据结构、持久化、Socket.IO 契约和触发逻辑。
2. 前端清单展示、编辑表单和状态同步。
3. 测试、README、CHANGELOG 和诊断报告补充。

如果保持第一版范围，适合作为一次小到中等规模迭代。
