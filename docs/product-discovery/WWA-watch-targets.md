# WWA：目标价观察清单

## 背景

目标价观察清单用于补充现有固定阈值预警。它让用户保存多个关注价位，并在触发后复用现有警报记录和通知链路。

本拆分基于 [PRD-watch-targets.md](/Users/dev/Code/GoldMonitor/docs/product-discovery/PRD-watch-targets.md)，第一版只做本地单机能力，不做云同步、自动交易、自动风险分析和复杂策略模板。

## Item 1：建立观察清单后端模型与持久化

**Why:** 用户需要重启后仍能保留观察价位。稳定的本地数据模型是后续触发、前端展示和诊断导出的基础。

**What:** 新增 `watch_targets.json` 持久化文件和运行时 `watch_targets` 状态。实现读取、保存、归一化和状态快照函数。字段遵循 PRD 中的第一版结构。

**Acceptance Criteria:**

- 文件不存在时返回空观察清单。
- 有效观察项可被正常读取、归一化和保存。
- 无效字段不会污染运行时状态。
- 保存失败时调用方可以获得明确异常。
- 新增契约测试覆盖空文件、有效数据、无效数据和保存回读。

## Item 2：提供观察项 Socket.IO 管理接口

**Why:** 前端需要通过现有实时通信机制管理观察项，并让多个已连接窗口保持状态一致。

**What:** 新增 `set_watch_target`、`delete_watch_target`、`toggle_watch_target`、`reset_watch_target` 等 Socket.IO 事件。新增 `watch_targets_updated` 和 `watch_target_error` 推送。

**Acceptance Criteria:**

- 新增观察项成功后，所有客户端收到最新清单。
- 编辑观察项成功后，所有客户端收到最新清单。
- 删除不存在的观察项时返回错误。
- 无效价格、无效单位、无效方向会返回错误。
- 修改价格或方向后，触发状态被重置。
- 契约测试覆盖新增、编辑、删除、停用、重置和无效输入。

## Item 3：接入价格刷新触发链路

**Why:** 观察清单只有在价格达到目标时自动提醒，才具备实际监控价值。

**What:** 在现有价格刷新成功链路中检查启用且未触发的观察项。达到条件后调用现有 `emit_alert`，并在观察项中记录触发时间和触发价格。

**Acceptance Criteria:**

- `rise_to` 在当前价格大于或等于目标价时触发。
- `fall_to` 在当前价格小于或等于目标价时触发。
- 停用观察项不会触发。
- 已触发观察项不会重复触发。
- 触发后警报记录包含来源和观察项 id。
- 触发后观察清单状态会保存并推送给前端。
- 不会自动调用风险分析模型。

## Item 4：在前端右侧预警区域展示观察清单

**Why:** 用户需要在现有监控工作台中直接查看和管理目标价，不应跳转到单独页面。

**What:** 在 `templates/index.html` 的右侧预警区域新增观察清单 UI。展示单位、方向、目标价、备注、启停状态和触发状态。提供新增、编辑、删除、启停和重置触发操作。

**Acceptance Criteria:**

- 初始连接时能渲染后端返回的观察清单。
- 新增、编辑、删除操作后前端状态与后端一致。
- 已触发、停用和启用状态有清晰区分。
- 无观察项时显示空状态。
- 错误信息显示在观察清单区域，不使用浏览器默认调试输出。
- 窄窗口下按钮和文本不重叠。

## Item 5：将观察清单纳入诊断和文档

**Why:** 本地工具需要便于排查问题。新增本地数据后，诊断和文档应告诉用户它保存在哪里，以及如何验证状态。

**What:** 更新诊断报告，加入观察清单文件路径、观察项数量和最近触发状态。更新 README 的本地数据和主要功能说明。更新 CHANGELOG。

**Acceptance Criteria:**

- 诊断报告包含 `watch_targets` 摘要。
- README 说明 `watch_targets.json` 的用途。
- CHANGELOG 使用中文说明本次新增能力。
- 文档不包含 AI 署名。
- 文档不包含敏感信息。

## Item 6：补充回归测试与手动验证清单

**Why:** 观察清单会接入价格刷新、告警、持久化和前端实时状态。需要用测试防止后续改动破坏核心链路。

**What:** 新增或扩展契约测试，覆盖后端数据模型、Socket.IO 事件、触发逻辑和不自动调用风险分析。补充手动验证步骤。

**Acceptance Criteria:**

- 后端契约测试可独立运行。
- 测试不会依赖真实网络行情。
- 测试使用临时目录隔离本地数据文件。
- 覆盖触发后写入警报记录。
- 覆盖已触发观察项不重复提醒。
- 手动验证步骤包含新增、触发、重置、停用、删除和重启恢复。

## 建议开发顺序

1. Item 1：后端模型与持久化。
2. Item 2：Socket.IO 管理接口。
3. Item 3：价格刷新触发链路。
4. Item 6：先补后端契约测试，锁住行为。
5. Item 4：前端展示与交互。
6. Item 5：诊断、README、CHANGELOG。

这个顺序先稳定数据和契约，再做界面，可以减少返工。
