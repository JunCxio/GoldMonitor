# GoldMonitor 下一批功能扩展想法

## 机会理解

当前产品已经具备实时金价展示、多源行情回退、阈值与波动预警、邮件和 Webhook 通知、风险分析助手、价格历史复盘、警报记录持久化、配置备份诊断、桌面悬浮条、Windows/macOS 安装与更新能力。

在未指定更细目标人群和商业目标前，本轮按以下假设梳理：

- 目标用户：需要长期关注黄金价格的个人用户、小型投资者、黄金消费决策用户。
- 主要目标：提高行情判断效率、降低漏看关键变化的概率、提升本地工具的可靠性和复盘价值。
- 约束条件：保持本地优先，不新增复杂账号体系；避免后台自动消耗模型 token；优先复用现有 Socket.IO、SQLite、本地设置和单页工作台结构。

## 三视角想法

### 产品经理视角

1. **预警策略模板**
   - 将上涨、下跌、关键价位、波动提醒组合成可保存的策略模板，如“短线观察”“长期买入关注”“高风险静默”。
   - 价值：降低重复配置成本，适合不同观察阶段快速切换。

2. **预警复盘报告**
   - 对一段时间内触发的预警、后续价格走势、相关新闻和风险分析结果生成复盘摘要。
   - 价值：把“提醒记录”升级为“判断质量回顾”。

3. **目标价观察清单**
   - 支持用户维护多个关注价位，每个价位包含方向、备注、有效期和触发后动作。
   - 价值：比单一阈值更贴近真实观察场景。

4. **行情健康评分**
   - 基于行情源成功率、缓存回退、响应耗时和多源偏差形成可读评分。
   - 价值：用户在价格异常时能判断是行情变化还是数据源不可靠。

5. **定时摘要通知**
   - 在用户设定的时间发送日内摘要，包括开高低收、主要波动、触发提醒和风险摘要。
   - 价值：从实时盯盘扩展到低打扰的日常关注。

### 产品设计视角

1. **预警设置向导**
   - 用分步表单引导用户选择观察目标、价格方向、通知渠道和静默规则。
   - 价值：降低新用户理解“预警阈值”和“通知规则”的门槛。

2. **事件时间轴**
   - 在历史复盘中以时间轴展示价格点、预警、风险分析、相关新闻和用户备注。
   - 价值：比列表和图表分散展示更适合复盘。

3. **风险分析对比视图**
   - 支持并排查看两次风险分析的结构化字段、风险评分卡和行情快照。
   - 价值：帮助用户理解风险判断如何随行情变化。

4. **悬浮条快速操作**
   - 在桌面悬浮条或菜单栏中增加快速静默、刷新、打开预警详情、查看今日摘要。
   - 价值：减少打开主窗口的频率。

5. **数据异常可视化**
   - 当多源偏差、缓存回退或刷新失败时，在主价格卡和数据源面板以统一状态展示。
   - 价值：让异常状态更容易被注意到，同时避免用户误解价格本身。

### 工程师视角

1. **预警规则数据模型升级**
   - 将当前按类型展开的阈值字段升级为规则列表，支持备注、启停、有效期、冷却、通知渠道覆盖。
   - 价值：为策略模板、观察清单和更复杂告警打基础。

2. **事件统一存储**
   - 建立统一事件表，保存价格事件、预警事件、风险分析事件、新闻关联和用户备注。
   - 价值：支撑时间轴、复盘报告和导出能力，减少多个列表各自拼接。

3. **本地任务调度器**
   - 增加轻量本地调度，统一管理定时更新检查、新闻刷新、定时摘要、数据清理和周期性健康评估。
   - 价值：当前后台循环较分散，后续周期任务会更容易维护。

4. **行情源适配器接口**
   - 将 Stooq、新浪、GoldPrice、EastMoney、Frankfurter 等采集逻辑抽成统一适配器契约。
   - 价值：方便新增、禁用、排序和健康统计，也利于测试。

5. **导入导出格式版本化**
   - 为配置、阈值、价格历史、告警记录和诊断报告增加明确 schema version 与迁移逻辑。
   - 价值：随着功能扩展，降低本地数据兼容和恢复风险。

## 优先推荐的五个方向

### 1. 事件时间轴与复盘报告

一句话描述：把价格走势、预警、风险分析和相关新闻统一到可筛选的时间轴，并支持生成一段时间的复盘报告。

选择理由：

- 当前已有价格历史 SQLite、警报记录 SQLite、风险分析历史、相关新闻关联和图表事件标记，数据基础较充分。
- 用户价值明确：从“看见提醒”进一步变成“理解当时为什么提醒、提醒后发生了什么”。
- 差异化较强：比普通价格提醒工具更像本地行情观察日志。

关键假设：

- 用户有复盘需求，而不只是实时提醒需求。
- 现有价格历史采样频率足够支撑短周期复盘。
- 用户愿意在本地保留更多事件数据。

落地线索：

- 入口：历史复盘弹窗、警报详情、风险分析历史。
- 状态：新增当前复盘时间范围、事件类型筛选、选中事件。
- 数据结构：优先新增统一事件读取层，后续再考虑独立事件表。
- 接口契约：新增 `get_event_timeline`、`export_review_report` 一类 Socket.IO 事件。
- 持久化：复用 `price_history.sqlite3`、`alert_log.sqlite3`、`risk_analysis_history.json`，必要时新增 `event_notes.sqlite3`。
- 异常路径：历史为空、事件时间无法解析、数据源为缓存、风险分析内容缺失。

### 2. 目标价观察清单

一句话描述：支持维护多个带备注、方向、有效期和触发状态的目标价，替代只能配置固定几类阈值的使用方式。

选择理由：

- 与金价监控核心目标最直接相关。
- 现有阈值模型已经支持上涨、下跌、关键价位和波动提醒，但表达能力偏固定。
- 可以先以独立清单形式上线，风险低于一次性重构全部预警规则。

关键假设：

- 用户会同时关注多个目标价，而不是只需要一组上下限。
- 备注、有效期和触发状态能显著提升后续回看价值。
- 现有右侧预警面板仍有足够空间容纳清单交互。

落地线索：

- 入口：右侧预警区域新增“观察清单”分组。
- 状态：观察项列表、启停状态、触发状态、选中编辑项。
- 数据结构：`watch_targets` 列表，字段包含 `id`、`mode`、`direction`、`price`、`note`、`expires_at`、`enabled`、`triggered_at`。
- 接口契约：新增设置、删除、切换、确认触发的 Socket.IO 事件。
- 持久化：可先写入独立 `watch_targets.json`，稳定后再迁入 SQLite。
- 异常路径：价格无效、过期目标、重复目标、当前价格缺失、配置目录不可写。

### 3. 行情健康评分

一句话描述：把多源状态、缓存回退、响应耗时和价格偏差汇总为清晰的行情可信度评分。

选择理由：

- 当前已经有数据源健康面板和多源对比状态，扩展成本相对可控。
- 能直接增强用户对当前价格的信任判断。
- 与风险分析助手的数据可信度字段可以形成一致体验。

关键假设：

- 用户需要知道“价格是否可信”，而不只是知道“价格是多少”。
- 多源偏差阈值和缓存年龄可以转化为容易理解的评分。
- 当前数据源样本数量足以形成稳定判断。

落地线索：

- 入口：主价格卡、数据源健康面板、风险分析快照。
- 状态：健康评分、评分等级、扣分原因、最近更新时间。
- 数据结构：在 `source_comparison_state` 或新增健康摘要中加入 `score`、`level`、`reasons`。
- 接口契约：扩展 `source_health_updated` 与 `price_update` 负载。
- 持久化：短期不必持久化，诊断报告可包含最近健康快照。
- 异常路径：仅一个源可用、全部源失败、使用缓存、响应耗时缺失。

### 4. 预警策略模板

一句话描述：把一组价格阈值、波动规则、冷却、静默和通知开关保存为模板，支持一键切换。

选择理由：

- 直接提升已有预警能力的可用性。
- 适合不同市场状态或不同用户任务，如“买入观察”“高波动提醒”“夜间静默”。
- 与配置导入导出能力天然兼容。

关键假设：

- 用户会在不同观察阶段切换规则，而不是长期使用一套设置。
- 一键切换不会造成用户误触或丢失现有配置。
- 策略模板的范围需要清晰，不应把所有设置都混在一起。

落地线索：

- 入口：预警阈值卡片或设置页通用设置。
- 状态：模板列表、当前应用模板、未保存更改提示。
- 数据结构：`alert_profiles` 列表，包含阈值、波动配置、通知分级、冷却、静默。
- 接口契约：新增保存模板、应用模板、删除模板、重命名模板。
- 持久化：可写入 `alert_profiles.json`，配置备份中纳入。
- 异常路径：模板字段缺失、模板版本不兼容、应用失败后的回滚提示。

### 5. 定时摘要通知

一句话描述：按用户设定时间发送日内或每日摘要，包含价格变化、触发预警、数据健康和最近风险分析。

选择理由：

- 将产品从实时盯盘扩展到低频跟踪，适合非专业用户。
- 复用现有邮件、Webhook、历史、告警、风险摘要能力。
- 对用户留存有帮助，但不强迫用户长时间打开主窗口。

关键假设：

- 用户愿意接收摘要类通知。
- 摘要内容需要严格基于本地数据，避免自动调用模型产生额外消耗。
- 本地后台常驻能力在 Windows/macOS 上足够稳定。

落地线索：

- 入口：设置页新增“摘要通知”分组。
- 状态：摘要启用状态、发送时间、发送渠道、上次发送时间。
- 数据结构：`summary_notification_enabled`、`summary_time`、`summary_channels`、`summary_last_sent_at`。
- 接口契约：扩展设置保存；新增手动发送测试摘要事件。
- 持久化：进入 `settings.json`，摘要发送记录可进入告警记录或独立事件。
- 异常路径：静默时段冲突、无价格历史、邮件或 Webhook 未配置、程序未运行导致错过发送。

## 不建议优先做的方向

- 账号体系和云同步：会显著改变本地工具边界，并引入隐私、服务端和运维成本。
- 自动交易或交易建议：风险高，且与当前风险分析助手“只做风险研判、不输出操作指令”的约束冲突。
- 大规模行情品种扩展：会稀释产品定位，且当前数据源、图表、通知文案都围绕黄金设计。
- 复杂插件系统：当前项目核心文件集中，过早抽象会增加维护成本。

## 建议下一步

如果要进入实现，建议先在前两项中选一个：

- 偏产品价值和差异化：优先做“事件时间轴与复盘报告”。
- 偏核心监控能力增强：优先做“目标价观察清单”。

选定后再进入 PRD 或 WWAS 拆解，明确验收标准、数据结构、Socket.IO 契约、持久化迁移和测试范围。
